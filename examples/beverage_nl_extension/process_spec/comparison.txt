新增250 mL三口味：单体JSON与四层配置对照
======================================

对象与来源
----------
基线：examples/beverage_full/example4，2 L和330 mL两规格、三口味，共六份配方。
四层候选：将examples/beverage_nl_extension/raw_response.json的原始增量应用到基线副本。
单体新增参考：examples/beverage_full/example5/legacy/中的orange_small.json、apple_small.json、
grape_small.json。这三份文件是评估侧预存参考，没有提供给历史模型，也不是模型此次生成的输出。
本对照依据已有配置和报告整理，不是一次新的模型调用。

统一计数口径
------------
JSON统一为四空格缩进、UTF-8、保留Unicode字符、LF换行。批次循环保持原样，不把执行次数
展开成重复源码；共享定义只计一次。单体完整总量包含每个配方JSON和设备注册表，四层完整
总量包含全部L1/L2/L3/L4、设备注册表及点位/配方/系统变量。Excel、说明和验证报告不是运行
配置，不加入配置行数。配置行数衡量文本规模，不等于实际开发工时或纯粹分层带来的独立收益。

四层修改范围
------------
首次原始输出共9项文件编辑操作，涉及5份文件：
  1. run_recipe.group.json：replace /args/1/max，规格索引上限1改2。
  2. system_variables.json：append /production_points，增加16个生产点。
  3. 同文件：append /recipes，增加三个250 mL配方。
  4—6. 同文件：分别append三个recipe_lookup口味行，加入新配方索引6、7、8。
  7—9. create三个L4：orange_small、apple_small、grape_small，参数分别[0,2]、[1,2]、[2,2]。

按保存格式的文本差异：
  run_recipe.group.json：增加1行、删除1行，净增0行。
  三个L4：分别增加15行、删除0行，合计净增45行。
  system_variables.json：增加186行、删除3行，净增183行。
  合计增加232行、删除4行，净增228行。
原33个生产点、六份配方和L4入口保持不变；L1/L2、设备表和其他L3过程保持不变。
具体原始差异保存在上一级changes.diff，已记录检查结果见validation_report.json。

工艺行为与已验证范围
--------------------
三个新配方继续执行全部十二阶段；每份配方两批、每批六瓶，各12瓶250 mL。
合计36瓶、9000 mL（9 L）。L3中的两层循环分别固定为2和6，不是动态读取配方数量字段。
原始输出未经配置修正。已有回放确认新增数据满足给定工程要求，原六配方的时间轨迹哈希不变。
九份正常配方的单体与四层执行得到相同的带时间戳轨迹，包括设备操作和模拟状态/产出。

另有11种既定故障场景，仅在旧配方索引0（orange_family）施加；不能写成三个新配方
各自都通过全部11项故障测试。故障得到对应预期错误码，不表示所有可能故障均已覆盖。
这些是确定性软件模拟结果，没有新增真实设备、灌装精度、卫生效果或包装装箱实验。
共享和参数化同时贡献文本减少；未提供同等参数化的非分层对照，不单独归因于分层。

重现
----
仓库根目录运行：
  python scripts/verify_beverage_process_spec.py
默认核对来源与JSON/CSV/XLSX补充材料，再调用原脚本重新应用和验证保存输出。
  python scripts/verify_beverage_process_spec.py --no-replay
只核对补充材料，不重放模拟。
  python scripts/verify_beverage_nl_extension.py
仅重放历史生成输出；不调用模型，不覆盖冻结输入和原始响应。

输入与候选对照的区分
--------------------
generation_input.json是事后整理的完整原六配方基线、工程数据和阶段说明，用于未来新任务。
process_spec.json和Excel含扩展后的九配方候选，供人类工艺说明及输出对照，不作为未见候选
答案的新生成输入。未来以generation_input.json和requirements_250ml.txt开展新生成时，
应另存输入哈希、生成来源、首次输出和验证结果，不回填或覆盖原provenance记录。
