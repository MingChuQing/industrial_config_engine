自然语言增量生成演示：在已有饮料流程上增加250mL
=================================================
本目录记录2026-10-03的一次新Codex辅助生成。它不属于论文中历史的DeepSeek实验，
也不是把先前构造的example5重新标注为LLM历史输出。实际模型版本和采样参数未由
当前委派接口提供，因此本记录不用于跨模型比较或生成成功率估计。

输入
----
prompt.txt：原始中文自然语言需求和配置编辑输出约定。
context.json：原有六配方的变量表、run_recipe接口、L4入口，以及给定工程参数。
generator_instruction.txt：本次委派任务的额外指令和过程消息。
provenance.json：输入、基线及原始输出哈希、生成来源和实验边界。

模型在不继承主对话历史的新任务中只读取prompt.txt和context.json。
协调者事先查看过完整基准，并据此给定模拟工程数据；这是一项有上下文的工作示例，
不是未见任务盲测。模型没有被提供example5输出、历史diff或参考单体JSON。
预置点位和流量是输入，不是模型从250mL容积推断出的物理设备参数。

原始输出
--------
raw_response.json：首次完整输出，保存后未经修复或二次生成。
外层changes只是记录文件增量的包装，不是控制引擎增加了新的配置语法。
模型给出三个L4对象、规格范围调整，以及点位/配方/查找表的必要增量。
验证器以固定规则应用这些编辑，再使用原有执行器解释实际的L1-L4文件。

重现保存输出的应用与验证
----------------------
在仓库根目录运行：
  python scripts/verify_beverage_nl_extension.py

这条命令重放已保存的模型输出并重新运行验证，不调用或重新生成LLM响应。
验证先核对冻结输入和基线，检查修改边界，再对照输入中的250mL容量、流量公式、
预置点位、设备及批次数验证字段。随后比较配置执行的带时间戳协议轨迹。
评估侧从既有example5复制三份固定单体参考；模型没有生成这些参考文件。
旧六配方还会与基线重新运行的轨迹比较，验证原有行为保持不变。
只在build/beverage-nl-extension/写入候选和结果，不覆盖已存基准或原始模型输出。
任何失败返回非零退出码，失败不是自动修复指令。

本例使用确定性软件模拟，不证明实际灌装精度、现场安全或一般LLM生成可靠性。
若本次原始输出通过验证，应报告无需修正；不能为了演示错误而把人工注入的缺陷
伪装成模型初稿。另有18类配置变异实验负责展示自动检查的能力和遗漏。
